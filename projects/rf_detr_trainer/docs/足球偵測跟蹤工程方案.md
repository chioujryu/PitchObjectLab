# 工程方案:單相機雲台拍攝、非正規野球場地、持續性極小足球的偵測與追蹤

## 摘要(TL;DR)
- **採用雙堆疊偵測器策略** — 一個以熱圖(heatmap)為基礎、吃多幀輸入的足球專用偵測器(WASB / TrackNet 系列),以原生解析度搭配 SAHI 切片(tiling)與 P2 高解析度偵測頭執行 — 才能在球於每一幀都只有 <10–15 像素的情況下維持高召回率;再搭配一個 YOLO/RF-DETR 的「球員 + 球」偵測器來處理多目標場景。
- **以「先追蹤、後篩選」的方式挑選主球**:偵測出**所有**的球,跑一個帶相機運動補償的多目標追蹤器(BoT-SORT 或 UCMCTrack),用草地分割(SAM2 / DeepLab / HSV)加上球員凸包(convex hull)框定有效區域,接著依「與最密集球員群集的距離」(DBSCAN)以及「正在被踢」線索為每條球軌跡評分,並加上遲滯(hysteresis)機制避免主球在多顆球之間閃爍跳動。
- **在 4 張 RTX 5090 上**(每張 32 GB GDDR7、頻寬 1,792 GB/s ≈ 1.79 TB/s、21,760 個 CUDA 核心、680 個第 5 代 Tensor 核心、3,352 FP4 AI TOPS、575 W、2025 年 1 月上市、定價 $1,999、**沒有 NVLink — 多 GPU 只能走 PCIe**):即時管線用 1 張 GPU 做偵測(TensorRT FP8/FP16)、1 張跑熱圖球網、1 張做分割/追蹤、1 張當餘裕;離線管線則以影片分片做平行化,並額外加上 RAFT 光流、SAMURAI 單目標還原,以及超解析度(在劣化的 SoccerNet 影格上,超解析度讓「球 + 球員」mAP 提升約 12%)。

## 重點發現(Key Findings)
1. **標準邊界框偵測器在持續性極小球上會失效。** COCO 將「小物件」定義為面積 <32×32 像素,而偵測器在小物件相較大物件通常會掉約 30 個 mAP;tiny-object 文獻則把「極小」定義為 <16×16 像素。對一顆只有幾像素的球而言,吃多幀連續影格的熱圖偵測器(WASB、TrackNet)是已被驗證的作法 — WASB 在足球資料上以 4 像素的容忍度進行評估。
2. **熱圖球偵測器在足球基準上領先。** WASB(Tarashima、Abdul Haq、Wang 與 Tagawa,NTT Communications,BMVC 2023;HRNet backbone、288×512 輸入、3 幀連續影格、約 1.5M 參數)在足球資料集上達到 **F1 88.2 / Accuracy 97.9 / AP 86.2**(Table 2,τ=4 像素),勝過 TrackNetV2(F1 86.6 / AP 77.2)與 DeepBall(F1 44.5)。但 WASB 在設計上每幀最多只輸出一顆球 — 這對「多球」需求是個限制。
3. **相機運動補償技術已經成熟,而且是必要的。** BoT-SORT 的 GMC(ORB / 稀疏光流 + RANSAC 仿射)、UCMCTrack(均勻地平面補償,單 CPU >1000 FPS、純運動)、Norfair 的光流相機運動估計,以及離線用的 ECC/RAFT,全都能直接處理雲台平移(panning)的問題。
4. **標準場地配準在非正規場地上很可能失效。** SoccerNet 的相機校正方法偵測線條/關鍵點,再把單應性(homography)擬合到正規球場模板上;在沒有正規線條的情況下,這套方法就破功了。穩健、不依賴標線的替代方案是草地分割(HSV / 綠色色度;微調後的 DeepLab 可達 IoU 0.98;或 SAM2/Mask2Former)與球員凸包取交集。
5. **主球挑選是個可解的啟發式問題。** 球員群集(DBSCAN / 凸包 / 質心)定義出「動作發生在哪裡」;球與球員的距離加上控球線索可挑出比賽用球;時間遲滯 / 匈牙利演算法(Hungarian)指派則讓選擇保持穩定。
6. **4 張 RTX 5090 對即時與離線都綽綽有餘**;這個工作負載受偵測端制約,離線時則是高度可平行的,而 Blackwell 的 FP8/FP4 tensor 核心讓重型模型(以及超解析度)都很便宜。

## 細節(Details)

### (A) 持續性極小球偵測
核心問題:球在**每一幀**都只有 <10–15 像素。以下三種互補技術必須結合使用。

**A1. 熱圖、多幀球偵測器(主力)。** TrackNet 系列與 WASB 是專為「高速且極小的物件」而設計。它們吃數張堆疊的連續影格,回歸出一張球位置的高斯熱圖,學的是運動/軌跡線索而非單幀外觀。
- **WASB**(Tarashima 等人,BMVC 2023,arXiv 2311.05237,repo `nttcom/WASB-SBDT`):HRNet backbone,並從 stem 移除 stride 以保留解析度,約 1.5M 參數,輸入 288×512,N=3 幀進 / 3 張熱圖出。在足球基準上達到 F1 88.2 / Acc 97.9 / AP 86.2,並以 7.8–16.8% AP 勝過六個先前的 SOTA 方法。超過閾值 δ=0.5 的連通元件(connected components)成為球候選;內建追蹤器再強制時間一致性。**關鍵限制:WASB 每幀最多預測一顆球,並明確指出「無法應用於同時使用多顆球的運動」。** 這點必須繞過(見 B)。註:WASB 的「Soccer」基準是 D'Orazio/Spagnolo 足球資料集,**不是** SoccerNet — 在比較數字時這點要釐清。
- **TrackNetV2**(288×512,3 進 / 3 出 MIMO,約 11.3M 參數):回報的測試 accuracy/precision/recall ≈ 85.2%/97.2%/85.4%;約 31.8 FPS。
- **TrackNetV3**(`qaz812345/TrackNetV3`):加入背景相減 + 軌跡修正(對被遮擋/漏掉的位置做內插);在其羽球測試集上回報約 97.5% accuracy / 98.6% F1。
- **TrackNetV4**(arXiv 2409.14543,ICASSP 2025):在 V2/V3 之上,以幀差(frame differencing)做即插即用的運動注意力圖(motion-attention maps);accuracy/precision/recall/F1 相對提升 +1.3/+1.2/+0.3/+0.7%。絕對數字對評估協定很敏感(一份獨立重現發現有很大落差),所以應把相對提升視為可靠的結論。
- **BlurBall**(arXiv 2509.18387):在 WASB 之上擴充出運動模糊感知的熱圖與速度估計 — 因為一顆快速的極小球通常都是糊的,所以很相關。

**A2. 原生解析度的切片 / SAHI(召回率增強器)。** 把 1080p/4K 影格縮到 640 會毀掉一顆只有幾像素的球。SAHI(Slicing Aided Hyper Inference,arXiv 2202.06934,repo `obss/sahi`)把全解析度影格切成重疊的小塊(例如 640×640、重疊 0.2),對每塊跑偵測器,再用 NMS/NMM 合併。在航拍小物件基準上回報 +6.8 AP(切片推論)到 +12.7 AP(加上切片輔助微調)的提升。SAHI 已整合進 Ultralytics(YOLO11/YOLO26)、MMDetection 與 Roboflow `supervision`(`sv.InferenceSlicer`)。代價:每幀很多小塊 → 用 5090 的吞吐量扛;一旦場地已知(見 D),只切場地 ROI 以減少小塊數量。

**A3. 高解析度 P2/P3 偵測頭(架構面)。** 標準 YOLO 偵測頭是 P3(stride 8)/ P4 / P5;P3 頭理論上可定位 8×8 像素物件,但下採樣會侵蝕召回率。**加入 P2 頭(stride 4,例如 160×160 特徵圖)可把覆蓋範圍延伸到約 4×4 像素物件**,對 <10 像素目標而言是最有效的架構改動(YOLO11-4K、SOD-YOLO、PPM-YOLOv11、GAME-YOLO 都證實了這點)。由於沒有感興趣的大物件,通常會把 P5 頭拿掉以省算力。這需要重新訓練(見 H)。

**A4. 超解析度(離線,即時可選)。** Seweryn、Cheć、Łukasik 與 Wróblewska 的〈Improving Object Detection Quality in Football Through Super-Resolution Techniques〉(arXiv 2402.00163)在劣化的 SoccerNet 影格上、於 Faster R-CNN 前套用 RLFN 超解析度:**320×240 影格放大四倍後 mAP@0.50:0.95 提升 12%**,而(在 ScienceDirect 後續論文 S1877750326000669 中)**從 320×240 放大六倍到 1920×1080 時 mAP@0.50:0.95 提升 >21%**,且對「球與遠處球員等較小物件」獲益最大。離線管線請用超解析度;若延遲允許,即時管線也可在場地 ROI 裁切上用(Blackwell FP4/FP8 讓超解析度很便宜)。

**A5. 時間聚合(temporal aggregation)。** 除了多幀輸入,還要利用軌跡連續性:對球軌跡做 Kalman 濾波、TrackNetV3 式的跨遮擋軌跡修正/補繪,以及只在候選跨 ≥2–3 幀都一致時才確認。這能抑制困擾圓形物件偵測器的誤報。

### (B) 多球的多目標追蹤
場上有多顆外觀相同的極小球(比賽用球 + 周邊/鄰場的球)。WASB/TrackNet 本身無法輸出多顆球,所以架構是:

**B1. 偵測所有的球。** 用一個帶 `ball` 類別的 YOLO/RF-DETR 偵測器(再加上熱圖網的 top-K 候選,而非只取 top-1)來列舉每一顆球。把信心閾值壓低以保住召回率,再靠追蹤 + 篩選去掉雜訊。

**B2. 外觀相同、極小物件的多目標追蹤。** 資料關聯(data association)是最難的部分:外觀 ReID 沒用(所有球長一樣),而在相機運動下,極小框在幀間的 IoU 幾乎為零。因此偏好**以運動 + 位置做關聯,而非外觀**:
- **BoT-SORT**(arXiv 2206.14651,repo `NirAharon/BoT-SORT`):Kalman 濾波 + GMC;強力的預設選擇;已整合進 Ultralytics 與 BoxMOT。
- **OC-SORT / Deep OC-SORT**:以觀測為中心(observation-centric),對非線性運動與短暫遮擋穩健;BoxMOT(`mikel-brostrom/boxmot`、`yolo_tracking`)加入了一個**專為「小型且/或高速物件、低 FPS 影片」設計的質心(centroid)成本函數**。
- **UCMCTrack**(Yi 等人,AAAI 2024,arXiv 2312.08952,repo `corfyi/UCMCTrack`):純運動,地平面 Kalman 濾波,以「映射馬氏距離」(Mapped Mahalanobis Distance)取代 IoU — 明確針對「邊界框之間沒有交集導致 IoU 失效」的情境設計,而這正是極小快速球的狀況。它僅靠運動線索就「在 MOT17 上不使用任何外觀線索而排名第一」,且「單 CPU 速度超過 1000 FPS」。
- **ByteTrack**:在第二階段關聯中保留低信心偵測 — 很有價值,因為極小球往往信心很低。
- **Norfair**:輕量、以點/質心為基礎、內建相機運動估計,並附 SAHI 範例;容易加入自訂距離函數。

對外觀相同的極小物件,應把以 IoU 為基礎的關聯換成**相機運動補償後的質心/馬氏距離**。當球交錯或彼此遮擋時會出現 ID 跳換;這是可以接受的,因為下游的主球篩選器會每幀重新挑選,並有時間平滑。

> **✅ 已實作（rf_detr_trainer inference）**:OC-SORT / Deep OC-SORT / BoT-SORT / ByteTrack 已透過 `boxmot`(pin `boxmot==13.0.0`)介接進影片推理,由 `inference.tracking.algorithm` 選擇(**預設 `circle`** 內建追蹤器),追蹤類別可設定(預設足球),各 boxmot 演算法的參數放在各自的巢狀區塊(`ocsort:`/`deepocsort:`/`botsort:`/`bytetrack:`)。BoxMOT 的質心成本函數正對應上文「小型/高速物件」需求;外觀 ReID 對「所有球長一樣」幫助有限,故 `ocsort`/`bytetrack` 純運動、免下載,`deepocsort`/`botsort` 才需 ReID 權重。實作細節見 [`tiny_ball_detection_tracking_modular_plan.md`](./tiny_ball_detection_tracking_modular_plan.md) 的 Module 3.1b。

**B3. 主球的單目標追蹤器後援。** 一旦主球被辨識出來,單目標追蹤器就能在雜亂中鎖定它:**SAMURAI**(arXiv 2411.11922)以運動感知記憶(motion-aware memory)改造 SAM2,可零樣本視覺追蹤「快速移動或自我遮擋的物件」,即時、免重新訓練;OSTrack/MixFormer 為替代方案。在場地 ROI 裁切上跑 SAMURAI/SAM2,在偵測器漏球時把球找回來。

### (C) 透過球員群集挑選主球
目標:從 N 條球軌跡中,挑出唯一的比賽用球 = 「最靠近球員群集 / 正在被踢的那顆」。

**C1. 偵測球員,定義「動作在哪裡」。** 偵測所有球員(同一次 YOLO/RF-DETR 推論)。每幀計算:
- **以 DBSCAN 找最密集群集**,作用在球員的地面位置上(DBSCAN 是足球空間分析的標準工具;用來找出主要的球員群與移動序列)。ε 依場景調整;最大/最密集的群集 = 進行中的比賽群。
- **球員質心**與**凸包**(足球分析中標準的戰術「團隊區塊」/ 覆蓋面積概念,控球階段往往顯示出較大的凸包面積)。動作質心是**最密集群集**的質心,而非所有球員的(周邊的人不該把質心拉走)。
- 可選用核密度 / mean-shift 估計球員密度,當作連續的「動作熱圖」。

**C2. 為每條球軌跡評分。** 把各種線索組合成每條軌跡的分數:
- **接近度**:球到最近球員腳邊、以及到動作質心的距離(越小越好)。經典的單球啟發式 — 「在假設場上只有一顆球、且其運動在物理上合理的前提下,選擇最靠近[球員]質心的球」 — 在此可推廣使用。
- **控球 / 正在被踢線索**:球落在球員腳邊半徑內(以環形判定控球,如運動追蹤專利與 Tryolabs 控球方法所述,即在閾值內腳邊最近的球員「擁有」球);球的運動與鄰近球員的動作相關;近期控球的連續性。
- 來自 (D) 的**界內加分 / 界外否決**。
- **軌跡品質**:軌跡年齡/信心,以及物理上合理的速度。

**C3. 隨時間保持穩定(防閃爍)。** **不要**每幀獨立取 argmax。請套用:
- **遲滯(hysteresis)**:只有當競爭者的分數連續 K 幀都超過現任主球一個邊際值時,才切換「主球」。
- 分數的**時間平滑**(EMA),以及跨時間對「主球」標籤做**匈牙利指派**,讓它鎖定同一個身分。
- 在短暫的偵測中斷期間,維持上一顆主球(track buffer),並以 (B3) 的單目標追蹤器橋接。

### (D) 不依賴標線的場地邊界偵測
**D1. 為何標準配準會失效。** SoccerNet 的相機校正 / 球場配準方法(PnLCalib、SoccerNet 2023 校正冠軍等)偵測線條交點與場地標線關鍵點,再把單應性擬合到已知的正規球場模型。這些論文指出交點「以清晰的幾何標記標示」,且單應性標註「往往未考慮鏡頭畸變」。在沒有正規線條、幾何也非標準的野球場地上,根本沒有可供配準的模板 — 這些方法無法產生可靠的邊界。

**D2. 草地 / 比賽表面分割(不依賴標線)。** 直接分割綠色的比賽表面:
- **以顏色為基礎(便宜、快速)**:HSV/色相門檻,或綠色色度分析;〈A fully automatic method for segmentation of soccer playing fields〉(Nature Sci. Reports 2023)結合正規化綠色 + RGB 色彩失真與區域層級的後處理,以剔除非場地的綠色。RoboCup 系統會把地平線以下的綠色區域取凸包當作場地。
- **以學習為基礎的分割(穩健)**:CNN 草地分割器 — Homayounfar、Fidler 等人的〈Soccer Field Localization from a Single Image〉(arXiv 1604.02715)微調 DeepLab,草地 vs 非草地達到 **IoU 0.98**。若要零樣本/少樣本,**SAM2**(可提示、含影片記憶)或 **Mask2Former/DeepLabv3+** 可分割場地表面並跨幀傳播遮罩。SAM2 的記憶庫使它很適合在相機平移時維持場地遮罩。

**D3. 用球員凸包當作不依賴標線的場地代理。** 所有球員的凸包(+ 邊際)在不對場地外觀做任何假設的情況下框出有效比賽區 — 當草地顏色模糊時(磨損的場地、陰影、人工草皮),這是個穩健的互補。組合:**有效區域 = (草地遮罩) ∩ (膨脹後的球員凸包)**。落在此區域之外的球(周邊、鄰場)在 C2 中被否決。

**D4. 在平移下追蹤邊界。** 由於雲台持續平移,場地遮罩必須更新。兩個選項:(i) **每 N 幀重新分割一次**(SAM2 傳播,或每幀快速 HSV);(ii) 用 (E) 的 CMC 模組得到的每幀單應性/仿射來**扭曲(warp)前一張遮罩**,只在漂移時才重新分割。即時的便宜選擇是每幀 HSV 草地 + 球員凸包取交集;離線的精確選擇是 SAM2 傳播。

### (E) 相機運動補償(平移雲台)
背景持續移動,所以靜態相機假設會破功。
- **追蹤器內建 GMC/CMC**:BoT-SORT 透過相鄰幀間的影像配準估計剛體相機運動 — 關鍵點抽取 + 稀疏(Lucas-Kanade)光流加上以平移為基礎的離群值剔除,用 RANSAC 解出仿射矩陣,再修正 Kalman 預測。方法有 `files | orb | ecc`(以及 `sparseOptFlow`,Ultralytics 預設,對移動相機「在精度與效率間取得良好平衡」)。Deep OC-SORT 與 StrongSORT 也含 CMC 模組;UCMCTrack 把相機運動折入均勻地平面模型。
- **獨立模組**:Norfair 的 `MotionEstimator`(在強角點上做光流;「適用於相機平移與俯仰」,維持一個固定參考幀,在漂移時更新)。以 ORB/ECC 做影像配準求仿射/單應性。
- **離線 / 高精度**:**RAFT** 稠密光流求精確的幀間運動;ECC 做次像素對齊。用估出的單應性來(i)補償追蹤器預測、(ii)扭曲場地遮罩(D4),以及(iii)可選地穩定一個固定的「世界」座標系以做軌跡分析。
- **實務提醒**:由於球與球員是動態的,背景運動要從偵測框**之外**的關鍵點估計(稀疏配準的離群值剔除就是在做這件事);純平移的運動以仿射就能很好地近似,所以 ORB+RANSAC 仿射通常就足夠且便宜。

### (F) 即時 / 線上管線
每幀流程(目標 25–30 FPS):
1. **擷取**影格(1080p 或 4K)→ 在 GPU 上解碼(NVDEC)。
2. **CMC**:相對前一幀估計仿射/單應性(ORB+RANSAC 或 sparseOptFlow)。
3. **場地遮罩**:HSV 草地分割(快)經扭曲/更新;與球員凸包取交集 → 有效區域。後續工作都限制在此 ROI 內。
4. **偵測(GPU 0)**:帶 P2 頭的 YOLO26/YOLO11(TensorRT FP8/FP16),作用在 ROI 上,可選 SAHI 切片,產出球員 + 所有球候選。
5. **熱圖球網(GPU 1)**:WASB/TrackNet(3 幀緩衝)作用在 ROI 上,取高召回的極小球候選;把 top-K 與偵測器的球合併。
6. **追蹤(GPU 2/CPU)**:BoT-SORT(帶 GMC)或 UCMCTrack,作用在球**與**球員上;以質心/馬氏距離關聯。
7. **球員群集**:DBSCAN + 最密集群集質心 + 凸包。
8. **主球挑選**:為軌跡評分(C2),套用遲滯/EMA(C3);可選地把勝出者交給 SAMURAI 單目標追蹤(GPU 2/3)鎖定。
9. **輸出**:主球座標 + 軌跡;(可選地回授以驅動雲台)。

**GPU 配置(4 張 5090)**:GPU0 偵測器、GPU1 熱圖球網、GPU2 分割+追蹤+單目標追蹤、GPU3 餘裕/超解析度/備援或第二台相機。5090 的 32 GB 與 1.79 TB/s 頻寬可輕鬆容納所有模型;請用 TensorRT(Blackwell 原生支援 FP8;FP4 在穩定時可用)— NVIDIA 回報 TensorRT-for-RTX 的 FP8/FP4 在 5090 上相較 FP16 有大幅加速。由於 5090 **沒有 NVLink**,請把四張卡當成獨立的工作者(一張卡一個模型),而非倚賴快速的點對點模型切分。

### (G) 離線 / 後製管線
精度優先,延遲無所謂;把影片跨 4 張 GPU 分片(資料平行),或跑一條模型平行的鏈。
1. 對場地 ROI 做**超解析度**(RLFN/diffusion,FP4)→ 小物件 mAP +12–21%。
2. 用最大的模型做**偵測**(RF-DETR-L/XL、YOLO26x、DEIM-D-FINE-X)+ 全解析度 SAHI、較低閾值。
3. 對整段影片跑**熱圖球網**(WASB,取 AP 最佳的 oversampling 變體)。
4. **以 RAFT 做 CMC** 稠密光流 + ECC 做精確穩定;建立全域場地座標系。
5. **離線 MOT**:BoT-SORT/Deep OC-SORT(或 BoostTrack),接著用**高斯平滑內插(GSI)**填補空隙;雙向(前向+後向)追蹤。
6. **軌跡修正**(TrackNetV3 式)與 Kalman 平滑,補繪被遮擋的球位置。
7. 一旦主球已知,以 **SAMURAI/SAM2** 做長期單球還原;長片用 SAM2-Long 記憶樹。
8. **主球挑選**搭配完整的過去+未來脈絡(非因果遲滯 = 比即時更乾淨)。
9. 以 TrackEval(HOTA/MOTA/IDF1)與 SoccerNet dev-kit 指標做**評估**。

### (H) 資料與訓練
- **資料集**:SoccerNet-Tracking(Cioppa、Giancola 等人,CVPRW 2022,arXiv 2204.06918 — 201 段 30 秒序列、225,375 幀、3,645,661 個邊界框與 5,009 條 tracklet,取自 2019 瑞士超級聯賽 12 場完整比賽,1080p/25fps,含球員+裁判+球的 ID)、SoccerNet Ball Action Spotting(12 類)、SoccerNet-GameState;WASB-SBDT 的足球集(D'Orazio/Spagnolo 資料集,**不是** SoccerNet)。Roboflow 上有足球球/球員資料集。
- **領域差距(domain gap)**:上述全部都是轉播 / 高架 / 全景畫面;你的相機是低架的業餘雲台。預期會有很大的領域差距 — **你必須從實際機台收集並標註自己的影片**。優先取得數小時有代表性的野球影片。
- **極小物件的資料增強**:小球的 copy-paste(Kisantal 等人〈Augmentation for small object detection〉— oversampling + copy-paste 可提升小物件 AP)、Mosaic(Ultralytics:「對提升小物件偵測非常有效」)、MixUp/CutMix,以及**合成相機平移增強**(套用隨機仿射/單應性序列來模擬雲台)。用生成式/diffusion 的 copy-paste 補罕見構型。
- **偵測器訓練**:微調 YOLO26/YOLO11,加上 P2 頭(拿掉 P5),以高輸入解析度訓練;以你標註的球位置、搭配 HLSM 困難樣本挖掘訓練熱圖網(WASB)。在 4 張 5090 上用 DistributedDataParallel;32 GB 允許大輸入/大批次訓練。
- **標註策略**:對球做密集標註(熱圖網用點標註即可),球員用框;以半監督/自監督傳播(用 SAM2 預標、人工修正)來放大規模;部分標註幀 + 交叉驗證,如 TrackNet 所做。

### (J) 具體建議與注意事項
**建議的建置順序:**
1. 先收集 + 標註真實機台影片(最大的風險是領域差距)。
2. 把即時基線架起來:YOLO26(+P2、TensorRT FP8)+ BoT-SORT(GMC)+ HSV 草地∩球員凸包 + 接近度/遲滯主球挑選。量測極小球的召回率。
3. 平行加上 WASB 熱圖網以拉高極小球召回率;合併候選。
4. 加上 SAMURAI 單目標追蹤對主球做鎖定。
5. 建置離線管線(超解析度 + 大模型 + RAFT + GSI + 非因果挑選)以產出可當作 ground-truth 品質的輸出,並自動標註更多訓練資料。

**會改變方案的閾值:**
- 若僅靠偵測器+SAHI 的球召回率 <~70% → 熱圖網就從可選變成必備。
- 若球與球之間的 ID 跳換率很高 → 從 IoU 關聯改成 UCMCTrack 地平面馬氏距離或質心成本。
- 若草地分割不可靠(草皮/陰影)→ 倚賴球員凸包當作主要場地邊界。
- 若即時 FPS <25 → 把所有重型工作限制在場地 ROI 內、拿掉超解析度、改用較小的偵測器 + 只用熱圖網。

**注意事項 / 不確定性:**
- **WASB 單球限制**是真實存在的;多球需求迫使你用 top-K/合併的繞法 — 這不是 WASB 被驗證的方式,所以要實測。
- TrackNetV4 的絕對精度數字取決於評估協定;請倚賴相對提升。
- 2026 年特定的模型宣稱:YOLO26(2025 年 9 月發布,NMS-free,含 Small-Target-Aware Label 指派 / STAL)與 YOLOv13 的數字大多來自廠商/排行榜來源(Roboflow 排行榜、Ultralytics),應在你自己的資料上重新基準測試;部分 arXiv 上的「YOLO26」分析帶有 2026 年的編號,值得獨立查證。
- SoccerNet 的「ball action spotting」是時序動作定位,不是像素級球定位 — 別把它的 mAP 數字過度解讀為小球偵測精度。
- 所有引用的基準數字都來自轉播 / 標準解析度、25–30 FPS 的資料;你的低架、平移、非正規場景會不同 — 一切都要在你自己的影片上驗證。
- RTX 5090 沒有 NVLink,且每張卡 TDP 為 575 W;機箱的供電/散熱要依 4 張卡來規劃,並把多 GPU 規劃成各自獨立的單卡工作者。
