# RF-DETR Trainer Agent Rules

Apply these rules when changing this project.

1. Before implementation, inspect the request for contradictions, missing details, or safer alternatives. Then do broad web/source research when network access is available, summarize findings and the proposed change, and get developer confirmation before editing; if the task is strictly local/offline or network is forbidden, state that clearly before continuing. If a material tradeoff remains, ask for confirmation before editing.
2. When creating a new project, major tool, or standalone module, choose a clear project name that fits the purpose, domain, and expected users. Do not rename this project or existing public entrypoints without explicit confirmation.
3. Keep execution configs in `config/` grouped by category: `runtime`, `model`, `dataset`, `output`, task section, and `evaluation`. Execution configs must include all supported parameters with `#` comments explaining purpose and valid options. Dataset YAML files should remain in their framework-native format. Output folders must be configurable by parameters, placeholders, or plain string templates.
4. Any code path that writes outputs must save the config that created those outputs inside the output folder. Use UTF-8 and preserve simplified/traditional Chinese text.
5. Before writing images, videos, documents, metrics, caches, or checkpoints, print an output estimate with file count and disk usage, then require developer confirmation unless `--yes` or config confirmation bypass is enabled. Every output-producing entrypoint must provide a no-confirm execution path such as `--yes`.
6. If a path for saved photos or other outputs does not exist, create it with `mkdir(parents=True, exist_ok=True)`.
7. Python entrypoints must import `colorama`, call `colorama.init(autoreset=True)`, and include a triple-quoted `"""..."""` usage docstring. Long-running loops must use progress bars.
8. CUDA usage must be configurable as CPU-only, auto GPU, or specific GPU IDs. Code must work on Linux and Windows paths.
9. When adding packages or model/dataset downloads, first check the public IP region. Use China-friendly mirrors for China/HK/MO/TW regions and official sources elsewhere. The program must work whether the developer is using a VPN or direct network by detecting the observed public IP region and allowing mirror/source overrides when needed.
10. Prefer existing project helpers, vectorized data structures, and appropriate algorithms for the fastest practical hot-path performance. Keep DataLoader/worker-style parallelism defaulted to `2`, but preserve an explicit `num_workers: 0`. Train, test, and inference entrypoints must apply the shared `runtime.cpu` thread budget before numerical-library imports, divide it across active model processes, and expose the shared CPU CLI flags; ordinary module imports must not alter the caller's thread settings. Avoid unrelated refactors and preserve user-created files.
11. Maintain a `uv` virtual environment in the project folder. If no `.venv` exists, create it through `uv`; if it already exists, add new dependencies with `uv add` and keep `pyproject.toml`/`uv.lock` in sync so future setup only needs `uv sync`.
12. GPU PyTorch setup must auto-detect the computer configuration and choose the appropriate PyTorch build/index. Reuse the existing setup helper when possible, and follow rule 9 for region-aware mirrors.
13. Update `README.md` whenever entrypoint usage, config options, setup steps, or output behavior changes.
14. Every runnable script must produce useful log output. For output-producing runs, write logs or a log summary inside the output folder when practical.
15. For SAHI sliced RF-DETR tests, prevent duplicate boxes from small slices with same-class `GREEDYNMM` + `IOS` postprocessing by default. Do not use class-agnostic merging unless the config explicitly asks for it.
16. Standalone and scheduled RF-DETR test diagnostics must keep visual sample candidate filters separate from rendered-class filters. `visual_samples.render_class_ids/render_class_names` controls rendered classes for sampled visuals, while `error_cases.render_class_ids/render_class_names` controls rendered classes for error-case images.
17. Error-case diagnostics must default to football when no target class is configured, and must render both ground-truth and prediction boxes with prediction scores for missed, misclassified, and false-positive target-class cases.
18. Test metrics must include COCO-style overall metrics plus per-class mAP50, mAP50-95, precision, recall, F1, and per-class small/medium/large detection metrics.
19. SAHI target-class recheck must keep the first-stage box geometry, verify the object with a centered B*B second pass, fuse first/second confidence scores by config weights, and keep the box only when the fused score passes the configured threshold.
20. Train, test, and inference entrypoints must remain separate Python files. Shared behavior should live behind shared helper modules rather than making standalone entrypoints import each other.
21. Inference outputs must support RF-DETR image/video file, folder, and HTTP(S) media sources. Mixed image/video folders are allowed, and the same class ID must use the same bounding-box color across all rendered images and video frames in a run.
22. Train, test, and inference configs must support running all data or only the first N records. Use `all`/`null` for full data and positive integers for first-N limits. Keep train limits in `dataset`, standalone/scheduled test limits in the task test section, and inference source limits in `inference`.
23. Inference video configs must support `inference.video.start_time`/`end_time` for segment inference and `inference.video.max_seconds` with `all`/`null` for full selected ranges or a positive seconds value for partial video inference. Time values must accept seconds, `MM:SS`, and `HH:MM:SS`.
24. Train, test, and inference entrypoints must include a rough HH:MM:SS runtime estimate in the pre-run estimate, print elapsed HH:MM:SS when the process exits, and write `run_timing.json` inside the output folder when outputs were created.
25. Keep large datasets, caches, checkpoints, generated media, and run outputs out of git via `.gitignore`.
26. RF-DETR test and inference speedups must use real batched `model.predict([...])` paths, not only larger YAML values. Default to balanced batches (`test.batch_size`/`sahi.batch_size` 4, `inference.batch_size`/video detection batches 8), keep batch sizes configurable, and downshift on CUDA OOM before failing.
27. Inference video tracking is pluggable via `inference.tracking.algorithm`: `circle` (the built-in stdlib tracker in `rf_detr_video_tracking.py`, the **default**) plus `ocsort`, `deepocsort`, `botsort`, and `bytetrack` provided by `boxmot` (pinned `boxmot==13.0.0`). Each boxmot tracker's params live in its own nested sub-block (`inference.tracking.ocsort`/`deepocsort`/`botsort`/`bytetrack`); shared ReID/CMC keys and the circle/rendering keys stay at the `tracking` top level. Keep `algorithm: circle` byte-compatible with the prior behavior, keep `rf_detr_video_tracking.py` stdlib-only, and import boxmot lazily (only when a boxmot algorithm actually runs). Resolve the tracked class from `inference.tracking.target_class_ids`/`target_class_names` (default football) for every algorithm, and emit the same `predictions.jsonl` track fields and `tracking_summary.json` across algorithms. For appearance trackers (`deepocsort`, or `botsort` with ReID), follow rule 9: the default ReID weights download from Google Drive, so prefer a local `inference.tracking.reid_weights` path and reuse `scripts/setup_pytorch_uv.py:detect_region` for the China/HK/MO/TW check; `ocsort`/`bytetrack` need no weights.
28. Resolve every relative training, standalone-test, inference, demo, and TensorRT cache output path from the `projects/rf_detr_trainer` directory, independent of CWD and whether a same-named directory exists. Honor absolute paths unchanged and allow project-anchored `../` paths to intentionally escape the project. Keep scheduled/final test outputs nested under their training output. An empty TensorRT `cache_dir` must default to `runs/rf_detr/tensorrt_cache` inside this project.
29. Maintain Small detection presets as the full Stock, P2-only, TrackNetV5-only, and P2+TrackNetV5 matrix across train, test, and inference, using `rf_detr_{train|test|inference}_small[_{p2|tracknet_v5|p2_tracknet_v5}].yaml`. Keep Stock at the official 512 x 512 default, P2 at `[P2, P3, P4]`, and TrackNetV5 as `model.motion.type: tracknet_v5`, distinct from inference video tracking. Custom-architecture test/inference presets must require a matching checkpoint rather than silently substituting official Stock weights.
30. Keep `config/rf_detr_inference_large_p2_tensorrt_fp16_smoke.yaml` as the TensorRT compatibility preset for Large 704 x 704, one class, P2 `[P2, P3, P4]`, gradient checkpointing enabled, no TrackNetV5, FP16, fixed batch 1, 4 GiB workspace, and tracking disabled. TensorRT engines and manifests are machine/runtime-specific generated artifacts and must remain outside git. Documentation and committed configs must use placeholders rather than workstation-local checkpoint or media paths. If a 4 GiB build fails for workspace allocation, the only prescribed retry is 2 GiB; do not change model size, resolution, P2, or FP16.
